## ما لا يثبت هذا الإصدار

لا يُنشئ الفحص الإنتاجي أي مريض أو حجز أو موعد أو account اختبار، ولا يشغل K6 أو stress/concurrency على Production. حجية تكامل الحجز والـsnapshot والسعر وidempotency والسباق وIDOR مستمدة من Staging المعزول فقط. كذلك لم يُثبت إرسال OTP حقيقي، لأن تهيئة Twilio Verify غير موجودة ولا يُضاف مزود مدفوع ضمن شرط الكلفة الصفرية.

## القيود والحواجز

| العنصر | الحالة المطلوبة |
|---|---|
| OTP/SMS الحقيقي | **BLOCKED** حتى يوفر المشغل تهيئة مزود الرسائل ثم يعاد اختبارها بموافقة ونطاق آمن. لا يعتبر `phone_verified_at` الاصطناعي في Staging إثباتًا لرسالة حقيقية. |
| واجهة العميل التشغيلي | **BLOCKED**: فشل دخول fixture منفصل في Staging بـ`invalid_credentials` ولم يثبت مسار `/clinic/bookings` في رحلة Browser مستقلة؛ يلزم تشخيص بلا استخدام حسابات Production. |
| K6 booking/retry | **NOT TESTED**: لا يوجد ادعاء تحمل أو سعة 50,000 مستخدم. اختبار بحث Staging smoke السابق ليس بديلًا عن اختبار الحجز. |
| المواعيد التشغيلية | لا تظهر عروض مطابقة عامة في الفحص الحالي. يتطلب الأمر إدخال/نشر عيادات وعروض ومواعيد **حقيقية من المشغل المخول**؛ لا تُنشأ بيانات وهمية في Production. |
| حماية كلمات المرور المسرّبة | **WARN** من Supabase فقط؛ تحسين متاح في خطة أعلى ولا تُفعّل ترقية أو شراء تلقائيًا. |

## قواعد الرجوع والتشغيل الآمن

إذا ظهر فشل حرج بعد هذا الإصدار، يُعاد توجيه Production إلى deployment السابق `dpl_65J1617gNn3neDYr2c4ragYpHety` ثم يُعالج المصدر في فرع، ويُختبر في Staging قبل دفع `main` جديد. لا تستخدم rollback للنشر كبديل لعكس DDL: مهاجرات grants الحالية قابلة للمراجعة وتحتاج migration مصدرية صريحة إذا تطلب الرجوع تغيير صلاحيات قاعدة البيانات.

لا تضع مفاتيح أو JWT أو كلمات مرور أو dumps في Git أو الوثائق أو logs. لا تُطبق DDL مباشرةً خارج migration مصدرية، ولا تجرّب الحجز/OTP أو الضغط في Production.
