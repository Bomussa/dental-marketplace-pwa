# الحالة الإنتاجية الحالية — أسناني قطر / MMC-MMS

**آخر مراجعة موثقة:** 21 أغسطس 2026، بعد نشر الإيداع `4ca0ea6` والتحقق الحي. هذا الملف هو موجز الحالة التشغيلية الحالية، ويُقرأ مع [README الجذري](../README.md). لا يعيد كتابة التقارير المؤرخة السابقة؛ تلك تبقى أدلة لزمنها ونطاقها فقط.

> **النطاق الرسمي:** [www.mmc-mms.com](https://www.mmc-mms.com) و[mmc-mms.com](https://mmc-mms.com). التطبيق منصة مقارنة وطلبات حجز؛ ليس جهة تشخيص أو علاج. لم تنجح محاولة OTP المقصودة في 20 أغسطس في إرسال رسالة، وعادت `503` بأمان قبل إنشاء أي تحدٍ أو حجز؛ لذلك لا يُدّعى تسليم SMS خارجي حتى تكتمل تهيئة Twilio وإعادة الاختبار.

## الإصدار والتحقق الأخير

| البند | الحالة المثبتة |
|---|---|
| آخر تحصين موثق | أُغلق تسرب القراءة العامة المباشرة لكل كيانات العيادات التجريبية عبر RLS، بما فيها العيادة والفرع والممارسون والساعات والاستثناءات والعروض والمواعيد والمراجعات؛ الترحيلان البعيدان `20260819171711` و`20260819173555` موثقان في سجل الترحيلات. كما أضيفت مهلات وتحويل فشل مضبوط لاتصال Twilio Verify ولمحول نموذج الدعم الخارجي. |
| حالة النشر | إصدار الإنتاج المرتبط بالإيداع `4ca0ea6` في Vercel بحالة `READY`؛ يتضمن تحسين التقرير المالي بفهرس `(clinic_id, start_at)` ونطاقات زمنية قطرية قابلة للاستفادة من الفهارس، وتقييد فترة التقرير بخمس سنوات، والتحقق التقويمي الموحد للتاريخ، ومهلات موحدة لقراءات RPC في لوحتي الإدارة والعيادة ومسار البحث. كما يفصل بوضوح بين تعطل خدمة تقييد محاولات OTP (`503`) وبين تجاوز الحد الفعلي (`429`)، ويقيد قراءات الصحة والحساب والعيادة والنتائج، وعمليات التخزين الحساسة، وإنشاء وتنظيف الحسابات بمهلة خادمية 15 ثانية، ويوحد حارس وجهات العودة المشفرة بين الدخول وصفحة تأكيد الهوية. |
| بوابة الجودة | `npm run verify` نجح: فحص مسبق، TypeScript، ESLint، **77 اختبار وحدة**، وبناء إنتاجي. |
| اختبار المتصفح | `npm run test:e2e` نجح محلياً: **54 اختباراً** لمسارات سطح المكتب والهاتف، بما فيها الوصولية ورفض تسجيل الخروج من أصل خارجي ووجهة دخول خارجية أو شبيهة بها، ومنع القراءة العامة المباشرة للعروض والمواعيد التجريبية. |
| صحة الإنتاج | فحص حي بعد النشر عند `2026-08-21T06:16:05.724Z` نجح: `/api/health` وملف PWA ورؤوس الحماية أعادت `200` والتحققات المطلوبة؛ أظهر فحص الصحة كتالوجاً عاماً من 48 علاجاً. أظهر اختبار `POST /api/patient-phone-verification/start` المقصود سابقاً استجابة `503` آمنة بسبب عدم وجود تهيئة Twilio في Vercel. |
| بحث حي | نطاق 25 كم ظهر في نموذج المقارنة وحُفظ في رابط النتيجة وملخصها. يرفض `/api/search` تفضيل موعد غير صالح بحالة `400`. |

## السلوك التشغيلي الحالي

| المجال | الضمان المطبق |
|---|---|
| البحث والمقارنة | يختار الزائر علاجاً رئيسياً ثم نوعاً دقيقاً، وتفضيل موعد، ونطاقاً من 1 أو 5 أو 10 أو 25 أو 50 كم، ومعيار ترتيب. عقد التحليل موحّد للصفحة وواجهة API. |
| الترتيب | «أفضل توازن شامل» معيار مستقل موزون للسعر والتقييم والموعد والمسافة؛ لا يكرر «الأرخص أولاً». |
| الحجز | يبدأ فقط من موعد صالح وبمفتاح idempotency وملف مريض مكتمل وهاتف موثق. انتقالات الحجز الحساسة خادمية وذرية. |
| تقارير النشاط | الإدارة ترى نطاق المنصة، والمالك/المدير في العيادة يرى نطاق عيادته فقط. التجميع بالساعة أو اليوم أو الأسبوع أو الشهر بتوقيت `Asia/Qatar`، مع طباعة؛ تصدير CSV إداري فقط. التقرير المالي محكوم بخمس سنوات كحد أقصى وتواريخ تقويمية صحيحة، ويستخدم نطاقات زمنية قطرية قابلة للفهرسة. |
| التحديث اللحظي | الجداول التشغيلية المصرح بها منشورة على Realtime، والواجهات تستخدم سياسة تجميع وإعادة اتصال موحدة؛ لا تتجاوز RLS. تبقى أحداث الإدارة مجمعة قبل إعادة التحميل حتى لا تتحول الدفعات المتتابعة إلى تحديث لكل صف. |
| أداء اللوحات والبحث | تقرأ صفحات الحساب والعيادة والإدارة الجلسة الخادمية المشتركة لكل طلب، وتنفذ القراءات المستقلة المتأخرة بالتوازي، مع إعادة استخدام منسقات التاريخ. قراءات RPC التشغيلية لتحليلات الإدارة وتفاصيل حجوزات العيادة وحسابات المشغلين وبحث العروض مقيدة بمهلة 15 ثانية؛ الفشل ينتهي إلى حالة واجهة مضبوطة ولا يبقي الطلب معلقاً. لا يغير ذلك نطاق البيانات أو الصلاحيات أو منطق الحجز. فحص PWA المقيد للأصل الثابت في النطاق الرسمي نجح عند 5 و25 و50 طلباً متزامناً بنسبة 100%؛ لا يمثل ذلك اختبار حمل لمسارات API أو قاعدة البيانات. |
| الكتابات العامة والجلسة | مسارات الحجز والتسجيل وOTP والدعم وتثبيت الجهاز والتحليلات تتحقق من المصدر نفسه وحد الحجم ومعدلات الطلب قبل الكتابة. تسجيل الخروج يرفض الأصل الخارجي قبل إنهاء الجلسة، وتسجيل الدخول وصفحة تأكيد الهوية يقبلان وجهة داخلية آمنة فقط ويرفضان أيضاً الصيغ المشفرة للشرطات المائلة أو العكسية التي قد تُفسر خارج التطبيق. |
| اتصالات المزود الخارجي وحماية التخزين | اتصال Twilio Verify مقيد بمهلة 12 ثانية، ومحول نموذج الدعم مقيد بمهلة 15 ثانية، وعمليات RPC الخادمية وعمليات العيادة وإلغاء الحجز وإنهاء OTP مقيدة بمهلة 15 ثانية؛ فشل النقل أو مهلة الاتصال أو استجابة نموذج غير سليمة تتحول إلى فشل خدمة مضبوط ولا تترك طلباً معلقاً أو تكشف استثناءً داخلياً. كما تغلف مهلة 15 ثانية قراءات وكتابات الدعم، وتسجيل أحداث الاختيار، وتحديثات ملف المريض وتحديات OTP، وعمليات الحساب والإدارة والعيادة الحساسة، وإنشاء وتنظيف حسابات المرضى ومشغلي العيادات، وقراءات صفحة الصحة والحساب والعيادة والنتائج؛ انتهاء المهلة ينتج استجابة خدمة مضبوطة أو واجهة آمنة بدلاً من انتظار غير محدود. تعطل خدمة تقييد البدء أو التأكيد يعيد `503` واضحاً، أما تجاوز حد محاولات الحساب أو الهاتف أو الرمز فيعيد `429` مع `Retry-After`. |
| سرية التهيئة | بوابة النشر تمسح مفاتيح Supabase وTwilio وOpenAI والرموز ومفاتيح SSH الخاصة؛ لا تستثني إلا قيم المثال الموسومة `REPLACE_ME`، وقد اجتاز الفحص السلبي بقيمة وهمية طويلة. |
| بيانات حساسة | RLS هو طبقة فرض الوصول. سياسات التعديل العميلية المباشرة للحجوزات والدعم وتغيير حالة المراجعة مسحوبة؛ المسارات الخادمية المقيّدة هي الطريق التشغيلي المعتمد. ولا يمكن للقراءة العامة المباشرة إظهار أي كيان تابع لعيادة موسومة كتجريبية. |

## القيود الصريحة

لا يصح اعتبار أي تطبيق خالياً نظرياً من كل خطأ أو ثغرة مستقبلية. لا يدّعي هذا التقرير اختبار تحميل بحجوم الآلاف أو الملايين، ولا إثبات إرسال SMS: فمتغيرات `TWILIO_VERIFY_SERVICE_SID` و`TWILIO_API_KEY` و`TWILIO_API_SECRET` غير موجودة في إعدادات Vercel الحالية، ومحاولة OTP المقصودة عادت `503` بأمان قبل إنشاء تحدٍ؛ راجع [دليل تهيئة OTP الحي](LIVE_OTP_CONFIGURATION_EVIDENCE_2026-08-20.md). التحقق المسبق من تهيئة Twilio منشور ويعيد الفشل قبل أي تعديل ملف أو استهلاك حد. نجح فحص PWA ثابت للقراءة فقط عند 5 و25 و50 طلباً متزامناً من دون أخطاء HTTP في `2026-08-21T06:16:05Z`؛ عند 50 طلباً كان `P99` مقدارُه `3650.84ms`. هذا الأصل ثابت ولا يدعم ادعاء سعة تجارية أو سرعة مضمونة لمسارات API أو قاعدة البيانات. حماية كلمات المرور المسرّبة لدى Supabase ما زالت ميزة مرتبطة بخطة أعلى من الخطة الحالية؛ لم تُجرَ ترقية أو تكلفة تلقائية.
