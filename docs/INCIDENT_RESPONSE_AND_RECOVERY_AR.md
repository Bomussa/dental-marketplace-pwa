# دليل الاستجابة للحوادث والاستعادة — أسناني قطر / MMC-MMS

**الإصدار:** 1.0 — 20 أغسطس 2026
**النطاق:** الموقع العام، التطبيق التقدمي، Vercel، Supabase، المصادقة، عمليات الحجز الخادمية، وموفر OTP عند تهيئته.

> هذا الدليل تشغيلي؛ لا يتضمن مفاتيح أو رموزاً أو بيانات مرضى. لا يُنفذ أي حذف واسع أو استرجاع قاعدة بيانات إلا عبر مالك الخدمة المخول وبعد تثبيت القرار في سجل الحادث.

## 1. أدوار الاستجابة

| الدور | المسؤولية خلال الحادث |
|---|---|
| قائد الحادث | يحدد الشدة، ينسق القرار، ويوثق الخط الزمني والقرار النهائي. |
| مالك التطبيق | يفحص النشر وأخطاء التشغيل والمسارات العامة ويطبق الرجوع الآمن عند الحاجة. |
| مالك البيانات | يفحص صحة قاعدة البيانات وسياسات الوصول والترحيلات، ويقرر أي إجراء على البيانات. |
| مسؤول التواصل | يصوغ تحديثاً مختصراً ودقيقاً للمستخدمين أو العيادات عند تأثر الخدمة. |

يجوز أن يؤدي شخص واحد أكثر من دور في التشغيل المحدود، لكن لا يُنفذ استرجاع بيانات أو تدوير سر من دون مراجعة ثانية عندما تكون متاحة.

## 2. تصنيف الحوادث

| الشدة | مثال | أول استجابة | هدف الاستعادة |
|---|---|---|---|
| حرجة | كشف بيانات، تعطل الحجز أو الدخول لكل المستخدمين، أو اشتباه سر مكشوف. | إيقاف الأثر، تقييد الوصول، واستدعاء مالك البيانات فوراً. | البدء خلال 15 دقيقة. |
| عالية | فشل جزء رئيسي من البحث أو لوحة العيادة أو OTP المهيأ. | تثبيت النطاق، تفعيل صفحة أو رسالة آمنة، وتحديد آخر إصدار سليم. | البدء خلال 30 دقيقة. |
| متوسطة | تعطل وظيفة غير حرجة، خطأ عرض محدود، أو فشل تصدير إداري. | فتح حادث، تحضير إصلاح واختبار منع رجوع. | خلال يوم العمل نفسه. |
| منخفضة | خطأ نصي أو تجميلي لا يؤثر في سلامة القرار أو البيانات. | تسجيله في التحسينات والتحقق في الإصدار التالي. | حسب دورة الإصدار. |

## 3. بروتوكول أول 15 دقيقة

أولاً، سجّل وقت الاكتشاف، الرابط أو المسار المتأثر، المستخدم أو الدور المتأثر إن كان معروفاً، ورسالة الخطأ من دون بيانات شخصية. ثانياً، نفّذ فحصاً قراءة فقط عبر `npm run check:production` أو عبر `/api/health`، ثم راجع حالة النشر وأخطاء التشغيل. ثالثاً، إذا كان الأثر بعد إصدار محدد، حدد آخر نشر جاهز سليم قبل أن تقرر الرجوع.

لا تنشئ حجزاً تجريبياً أو OTP أو رسالة دعم أثناء تشخيص عام. لا تنسخ بيانات مرضى أو أسرار إلى تذكرة الحادث أو المحادثة أو ملف Git.

## 4. مسارات الاستجابة

### 4.1 تعطل واجهة أو إصدار

إذا أخفق `/api/health` أو ظهرت أخطاء تشغيل مرتبطة بإصدار جديد، افحص نشر Vercel أولاً. إن كان العطل واضحاً ومؤثراً، استعد آخر إصدار جاهز سليم. بعد الاستقرار، أنشئ إصلاحاً مستقلاً يمر عبر `npm run verify` و`npm run test:e2e` وفحص صحي لاحق. لا تستخدم الرجوع كبديل لإصلاح مخطط قاعدة البيانات.

### 4.2 اشتباه كشف بيانات أو تجاوز صلاحيات

أوقف أي مسار أو تكامل يعتقد أنه مصدر الأثر، واحفظ الحد الأدنى من معرفات الحادث والسجلات. راجع سياسات RLS والمنح ودوال الخادم ونشر الإصدار المتأثر. عند اشتباه سر، دوّره من مزود الخدمة أو مخزن الاستضافة أولاً، ثم ألغِ الجلسات أو المفاتيح المتأثرة بحسب قدرة المزود. لا تحذف سجلات تؤيد التحقيق.

### 4.3 تعطل قاعدة البيانات أو Realtime

افحص `/api/health` ثم حالة Supabase وتنبيهاتها. ثبّت ما إذا كان الأثر قراءة أو كتابة أو Realtime فقط. تجنب أي تغيير يدوي واسع في الجداول؛ طبّق فقط ترحيلاً مدروساً وقابلاً للتتبع عند الحاجة. تراجع عمليات الاستعادة والنسخ الاحتياطي مع مالك البيانات قبل تنفيذها.

### 4.4 فشل OTP أو مزود خارجي

تحقق من تهيئة متغيرات الخادم، وحدود المعدل، وحالة مزود الرسائل دون كشف المفاتيح. إذا كانت الرسائل غير متاحة، يجب أن تظهر رسالة تشغيل آمنة، ولا يجوز تجاوز التحقق الهاتفي أو اعتبار رقم غير موثق موثقاً.

## 5. التحقق من الاستعادة

لا يغلق الحادث لمجرد اختفاء الخطأ. يلزم توثيق وقت الاستعادة، الإصدار أو الترحيل المطبق، نتيجة `npm run check:production`، وعدم وجود أخطاء تشغيل جديدة في نافذة مراقبة مناسبة، وتحقق من المسار المتأثر من دون إنشاء بيانات غير لازمة. للحوادث الأمنية، يلزم أيضاً توثيق تغيير السر أو السياسة وتقييم البيانات المتأثرة بواسطة مالك البيانات.

## 6. مراجعة ما بعد الحادث

خلال يومي عمل من الإغلاق، يوثق الفريق السبب الجذري، الأثر الفعلي، الإجراءات المؤقتة، والإصلاح الدائم واختبار منع الرجوع. يحدّث دليل النشر أو سجل الترحيلات أو الاختبارات فقط عندما تصبح المعلومة حقيقة مثبتة، وليس لتغيير سجل تاريخي.

## 7. تمرين دوري مقترح

مرة كل ربع سنة، نفذ تمريناً غير متلف: فحص صحي، مراجعة آخر نشر جاهز، مراجعة قناة التنبيه، محاكاة قرار رجوع من دون تطبيقه، ومراجعة من يملك صلاحيات البيانات والأسرار. لا يتضمن التمرين إرسال SMS أو تعديل حجوزات أو استعادة قاعدة البيانات ما لم يكن له نطاق منفصل وموافقة محددة.
