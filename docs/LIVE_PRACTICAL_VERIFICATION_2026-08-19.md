# التحقق الحي العملي متعدد الطبقات — أسناني قطر / MMC-MMS

**تاريخ الجولة:** 19 أغسطس 2026

**النطاق:** الموقع الرسمي `https://www.mmc-mms.com`، مراقبة Vercel وSupabase للقراءة فقط، وبناء الإنتاج المحلي.
**قاعدة السلامة:** لم يُنشأ حجز أو ملف مريض أو عرض أو موعد أو رسالة SMS، ولم تُرسل أي بيانات شخصية؛ اقتصرت الرحلات المصدقة على حسابات الاختبار الموجودة والقراءات المصرح بها.

> هذا التقرير يثبت ما فُحص بالفعل في هذه الجولة. لا يمكن أن يثبت أي تقرير خلو نظام برمجي نظرياً من كل خطأ مستقبلي؛ لذلك يذكر الدليل ونطاقه والقيود صراحةً.

## ملخص النتيجة

| المجال | الدليل العملي | النتيجة |
|---|---|---|
| النطاق والصحة | حوّل `mmc-mms.com` إلى `www` بـ`308` عبر HTTPS. أعاد `/api/health` حالة `200` و`ok=true` و`database=true` و`server_operations=true` و48 علاجاً رئيسياً. | ناجح |
| رؤوس الحماية | ظهرت HSTS وCSP مقيّد و`X-Frame-Options: DENY` و`X-Content-Type-Options: nosniff` و`Referrer-Policy: strict-origin-when-cross-origin`. | ناجح |
| رحلة الزائر | تحققت الواجهة بالعربية والإنجليزية، العلاج والنوع الدقيق والموعد ونطاق المسافة والفرز، ثم حُفظ نطاق 25 كم في رابط النتائج وعرضت حالة عدم توفر آمنة. | ناجح |
| عقود الواجهة العامة | بحث صالح أعاد `200`، نطاق مسافة غير صالح أعاد `400`، تحليل اختيارات عبر `GET` أعاد `405`، حجز بلا جلسة أعاد `401`. | ناجح |
| منع الكتابة غير الموثوقة | تسجيل الخروج وتثبيت الجهاز من أصل خارجي أعادا `403 forbidden_origin` قبل أي كتابة. | ناجح |
| حسابات الاختبار والأدوار | ظهرت صفحة الحساب الاختبارية دون حجوزات، ولوحة العيادة بدور المالك مع بيانات العيادة فقط. حاول دور العيادة فتح `/admin` فعاد إلى الصفحة العامة ولم ير واجهة الإدارة. | ناجح |
| تقرير نشاط العيادة | غُيّر التجميع من اليومي إلى الشهري، وحُفظ في الرابط، وعرض نطاق العيادة ومجاميع شهرية بلا بيانات تعريفية للمرضى. | ناجح |
| مراقبة Vercel | لم توجد مجموعات أخطاء runtime في آخر 24 ساعة وقت الفحص. | ناجح |
| قاعدة البيانات والتبعيات | `npm audit --omit=dev` أعاد 0 ثغرات معروفة. | ناجح |

## إصلاح مؤكد ضمن الجولة

أظهرت مراجعة إعادة التوجيه أن عقد `passwordLoginSchema` كان يقبل أي نص يبدأ بـ`/`. قد يسمح ذلك نظرياً بمساري الشبكة `//host` أو الشرطة العكسية `/\\host` بالوصول إلى إعادة توجيه الدخول. حُصّن العقد ليقبل مساراً داخلياً فقط، وأضيفت اختبارات منع رجوع للمسارين. هذا إصلاح وقائي لعقد المصادقة وليس تغييراً في رحلة الدخول العادية.

| التحقق المحلي قبل النشر | النتيجة |
|---|---|
| اختبار عقد التحقق المستهدف | 16 اختباراً ناجحاً، ويشمل رفض `https://…` و`//…` و`/\\…` في `next`. |
| `npm run verify` | ناجح: فحص مسبق وTypeScript وESLint و64 اختبار وحدة وبناء إنتاجي. |
| `npm run test:e2e` | ناجح: 50 اختبار متصفح عبر سطح المكتب والهاتف، ومنها الحجز المحمي، CSP وPWA والرفض ذي الأصل الخارجي. |

## القيود والنتائج التي لا تُحوّل إلى ادعاء

| الموضوع | الوضع الصحيح |
|---|---|
| الرسائل والحجوزات الحقيقية | مستثناة من هذه الجولة عمداً، فلا يصح ادعاء تسليم SMS خارجي أو إنشاء حجز حي من هذا التقرير. |
| اختبارات الضغط الكبيرة | لم تُنفذ على الإنتاج. لا يمثل هذا التقرير اختبار آلاف أو ملايين الجلسات؛ يلزم بيئة معزولة وخطة توقف ومراقبة متخصصة. |
| دور إدارة المنصة | ثبتت حماية الإدارة ضد جلسة مالك عيادة. لم تُجرَ طفرة أو اختبار تشغيلي إداري لأن الجولة لا تنشئ أو تعدل بيانات. |
| تجميع سجل Supabase | كانت مصادر السجل متاحة، لكن استعلام التجميع الخاص برسائل الخطأ أعاد خطأ خلفياً من خدمة السجل؛ لم يُنسب ذلك إلى التطبيق. استخدمت مراقبة Vercel ومجسات الصحة والعقود كأدلة بديلة. |
| تحذير Supabase خارجي | بقي تحذير واحد: حماية كلمات المرور المسرّبة معطلة لدى Supabase Auth. لا يُفعّل تلقائياً من المستودع لأنه إعداد مزود وقد يرتبط بالخطة؛ لا يشكل دليلاً على كتابة أو صلاحية مفتوحة في التطبيق. |
