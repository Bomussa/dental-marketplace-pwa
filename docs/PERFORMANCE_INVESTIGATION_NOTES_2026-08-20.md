# ملاحظات تحقيق الأداء — 20 أغسطس 2026

> هذه ملاحظات قياس أولية، وليست ادعاءً بسعة تجارية أو اختبار تحمل شامل.

## مؤشرات الإنتاج المقروءة

استرجاع سجلات Vercel للإنتاج خلال آخر 24 ساعة أظهر حجماً محدوداً من الطلبات: 14 للصفحة الرئيسية، 11 للوحة العيادة، 7 للحساب، وطلباً واحداً فقط للبحث. أظهر تجميع حالات الاستجابة 53 حالة `200`، وحالتي `403`، وحالتي `503`. تعود استجابات `503` المرصودة إلى مسار OTP غير المهيأ في اختبار مقصود سابق، ولا توجد مجموعة أخطاء تشغيل غير معالجة مثبتة في المراقبة المتاحة.

## حالة قاعدة البيانات

أظهر مستشار أداء Supabase تحذيرات معلوماتية لفهارس غير مستخدمة، وهو متوقع في قاعدة تجريبية صغيرة منخفضة الحمل، وتحذيرات أداء بشأن تعدد سياسات RLS المسموح بها لبعض جداول التشغيل. لا تُحذف الفهارس أو تُدمج السياسات بلا اختبار صلاحيات مستقل، لأن ذلك قد يغير الوصول المطبق.

إحصاءات الجداول الحرجة صغيرة: 13 صفاً تقديرياً لكل من `branch_service_offers` و`availability_slots` و`branches`، وصفر للمراجعات والحجوزات. لذلك لا تصلح هذه البيانات لإثبات أداء عند آلاف العيادات أو المرضى.

نفذت خطة `EXPLAIN ANALYZE` مقيدة لدالة البحث العام مع نوع علاجي نشط. عادت بلا نتائج حالياً واستغرقت قرابة `227.9ms` مع `2279` صفحة مخزن مؤقت. وبسبب صغر العينة ودالة SQL، لا تُستنتج منها سعة مستقبلية؛ لكنها تثبت أن البحث العام مسار يحتاج مراقبة وقياساً في بيئة بيانات واقعية.

## تحسينات مصدرية آمنة منفذة محلياً

1. جرى تحويل ترتيب «أفضل توازن شامل» من إعادة حساب متكرر للمقاييس داخل مقارنة الفرز إلى حساب المقاييس مرة واحدة لكل عرض قبل الفرز.
2. جرى إعادة استخدام منسقات التاريخ في صفحة النتائج بدلاً من إنشاء منسق لكل عرض أثناء الرسم.
3. جرى تقييد أداة الحمل إلى أصول PWA ثابتة للقراءة فقط، بمستويات افتراضية 5 و25 و50 وبحد أقصى 50 طلباً متزامناً؛ وترفض مسارات API وأي مستوى أعلى.

## التحقق بعد التحسينات

نجحت بوابة `npm run verify` بعد التحسينات، بما فيها TypeScript وESLint و67 اختبار وحدة وبناء الإنتاج. كما نجح `npm run test:e2e` بنتيجة 54 اختبار متصفح ناجحاً. اختُبر حارس أداة الحمل مباشرة: رفض مسار `/api/health` قبل إنشاء اتصال، ورفض مستوى 51 طلباً متزامناً قبل إنشاء اتصال. وأعاد `npm audit --omit=dev` نتيجة صفر ثغرات معروفة في تبعيات الإنتاج.

## حدود لم تُغلق بعد

لا تزال رحلة OTP الحقيقية مرتبطة بتهيئة Twilio Verify، ولا تزال رحلة حجز إنتاجية كاملة تتطلب عرضاً وموعداً معتمدين. كما يلزم بيئة أداء معزولة وبيانات واقعية وSLOs معتمدة قبل أي اختبار بالحجم الكبير أو قرار توسع.
