## الإصلاحات المنفذة

تم اكتشاف خلل حقيقي في فحص ما قبل النشر: كان يتحقق من المسار غير الموجود `app/auth/confirm/route.ts`، كما كان نمط فحص الأسرار يتعامل مع القوالب والوثائق وملفات ترحيل الصلاحيات على أنها مواد سرية. صُحح المرجع إلى صفحة التأكيد الفعلية `app/auth/confirm/page.tsx`، واستُبدل الفحص بنمط يلتقط مفاتيح `sb_secret_*` طويلة أو JWT صالحًا شكليًا أو مفاتيح خاصة، من دون تعطيل القوالب أو التوثيق المشروع.

أصبحت بوابة `predeploy:check` جزءًا من `npm run verify` و`vercel-build`، ولذلك تدخل في التحقق المحلي وفي بناء Vercel نفسه. أُعدت مواءمة مقابلة لسير عمل GitHub Actions، لكن GitHub رفض رفع تعديل ملف `.github/workflows/ci.yml` لأن رمز الوصول الحالي لا يحمل صلاحية `workflows`. لم يُدّعَ تعديل هذا الملف أو إدخاله إلى الفرع الرئيسي.

| الملف | الإجراء | الأثر |
|---|---|---|
| `scripts/predeploy-check.mjs` | إصلاح مرجع صفحة تأكيد الدخول وقاعدة كشف الأسرار. | أصبح الفحص ينجح في الحالة الآمنة ويمنع الانحدارات الفعلية. |
| `package.json` | إضافة `predeploy:check` وإدراجه ضمن أوامر الجودة والبناء على Vercel. | لا يمكن تجاوز فحص المسارات والأسرار ضمن التحقق المحلي أو بناء Vercel. |
| `docs/LOCAL_UI_VERIFICATION_2026-08-17.md` | تحديث أدلة المعاينة المحلية والمستضافة. | توثيق مسارات الاختبار ونتائجها الفعلية. |

## اختبار الموقع الفعلي

تم فتح النسخة المستضافة من المشروع عبر وصلة وصول مؤقتة؛ فالرابط العام محمي بـVercel Authentication. تحمّلت الصفحة الرئيسية العربية فعليًا، وعرضت 25 علاجًا و46 نوعًا علاجيًا، وانتقل البحث إلى صفحة النتائج دون خطأ. أعادت صفحة النتائج `0` عروض مع رسالة صادقة، ولم تظهر عيادات DEV الاصطناعية.

كما اختُبرت واجهات API من جلسة الموقع المستضاف. أعادت `/api/health` حالة `200` مع `database: true` و`server_operations: true`، وهو دليل أن أسرار عمليات الخادم موجودة في النسخة المستضافة. وأعادت محاولة الحجز غير الموثقة `/api/book` الحالة `401`؛ لذلك لم تُنشأ حجوزات أو تغييرات بيانات كجزء من الاختبار.

> لا يمكن اختبار حجز ناجح على الموقع المستضاف حاليًا من دون حساب مستخدم مرخّص وعرض عام مؤهل بموعد حقيقي. بيئة DEV الحالية تحتوي عروضًا مرتبطة بعيادات اصطناعية، ويستبعدها البحث العام عمدًا؛ لذلك إنشاء عرض عام مزيف لاختبار الحجز سيكون مخالفًا لتحصين المنتج ولا يدخل ضمن هذا التسليم.

## حالة النشر

نسخة الإنتاج المستضافة الحالية تعمل ويمكن اختبارها. ومع ذلك، فإن نشرَي Vercel اللذين يُطابقان الالتزامين الأحدث قبل هذه الدفعة ظهرا بحالة `BLOCKED` مع رابط تشخيص Vercel يشير إلى **إعداد تعاون/حساب**، وليس خطأ بناء أو وقت تشغيل. لا يمكن حل هذا النوع من الحظر من المصدر أو بتعديل كود التطبيق؛ يلزم أن يصحح مالك فريق Vercel إعداد التعاون المرتبط بمستودع GitHub أو صلاحية نشر الالتزامات.

لا ينبغي تجاوز الحماية أو إنشاء مشروع نشر بديل تلقائيًا، لأن ذلك يغير مسار الإنتاج المعتمد. بعد تصحيح إعداد التعاون، يكفي دفع الالتزام الحالي أو إعادة تشغيل النشر من Vercel، ثم التحقق من أن حالة النشر تصبح `READY` وأنها تشير إلى الالتزام الأخير.

## حدود صريحة

المساعد الذكي يحتاج إعداد قاعدة المعرفة المعتمدة ومفتاح بوابة الذكاء الاصطناعي في بيئة النشر كي يرد على المستخدمين؛ لم يتم اختراع مفاتيح أو إنشاء محتوى معرفة غير معتمد. كما لم يُختبر Magic Link أو الحجز الناجح أو إرسال الدعم لأن ذلك يحتاج حسابًا فعليًا وبيانات تشغيلية معتمدة، وأي محاولة تتجاوز هذه الحدود قد ترسل رسائل أو تنشئ سجلات حقيقية.

**الخلاصة:** إصلاحات المصدر وبوابات الجودة والواجهة المستضافة اجتازت الاختبارات المتاحة فعليًا. يتبقى إجراءان تشغيليان خارج الكود: رفع حظر تعاون Vercel حتى تتلقى النسخة المستضافة الالتزام الأخير، ومنح رمز GitHub المستخدم صلاحية `workflows` إذا أريد رفع مواءمة CI المقترحة.
