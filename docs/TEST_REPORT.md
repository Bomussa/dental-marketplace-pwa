# تقرير الاختبارات الحالي — أسناني قطر / MMC-MMS

> هذا التقرير يلخص بوابة الجودة الحالية. تظل تقارير الاختبارات المؤرخة في `docs/` أدلة تاريخية لنطاقها؛ لا تعاد صياغتها لتغيير سياقها.

## النتائج المؤكدة في آخر بوابة جودة

| الفحص | النتيجة | النطاق |
|---|---|---|
| `npm run verify` | ناجح | `predeploy:check` ثم TypeScript وESLint وVitest وبناء الإنتاج. |
| Vitest | **77 اختباراً ناجحاً** | العقود، المال والتسعير، البحث والفرز، الحجز، الصلاحيات، الأمن، النشاط، الترجمة وPWA، وفحص تهيئة Twilio المسبق وفشل النقل المتحكم به، ومحول الدعم ذي المهلة واستجابة المزود غير السليمة، وحارس إشعارات العيادة اللحظية، ومهلات RPC والعمليات الخادمية العامة، وحد التقرير المالي والتحقق التقويمي الموحد من التاريخ. |
| Playwright | **54 اختباراً ناجحاً** | سطح المكتب والهاتف، البحث، العزل، الدخول، المسارات المحمية، حارس أصل تسجيل الخروج، القراءة العامة المباشرة لكل كيانات العيادات التجريبية، CSP وPWA والوصولية. |
| `npm audit --omit=dev` | **0 ثغرات معروفة** | تبعيات الإنتاج في وقت الفحص. |
| فحص إنتاجي قراءة فقط | ناجح عند `2026-08-21T05:36:53Z` | الصحة وملف PWA ورؤوس الحماية على `www.mmc-mms.com` أعادت `200`؛ أظهر فحص الصحة 48 علاجاً عاماً. لا ينشئ الفحص بيانات حقيقية. |
| حمل PWA مقيد | ناجح حتى 50 طلباً متزامناً | أصل ثابت للقراءة فقط، 100% نجاح في الجولة الأخيرة عند 5 و25 و50 طلباً؛ كان `P99` عند 50 طلباً `2238.95ms`. تفشل الأداة الآن برمز خروج غير صفري عند إخفاق أي طلب حتى لا تُفسر الجولة الفاشلة على أنها نجاح. لا يقيس الاختبار حجزاً أو قاعدة بيانات أو سعة تجارية. |

## أهم حالات التغطية

| المجال | ما تثبته الاختبارات |
|---|---|
| البحث | اختيار العلاج والنوع الدقيق، تحليل موحد للصفحة و`/api/search`، نطاق 25 كم، ورفض تفضيل موعد غير صالح بدلاً من تحويله بصمت. |
| الترتيب | معايير الأرخص والأقرب والأعلى تقييماً والأسرع مستقلة، و«أفضل توازن شامل» موزون ولا يعيد استعمال ترتيب السعر. |
| الحجز | مفتاح idempotency، متطلبات ملف المريض والتحقق من الهاتف، وتفادي بناء حجز مكرر ضمن منطق الخادم. |
| الصلاحيات | حواجز مسارات المريض والعيادة والإدارة، وعرض بيانات العيادة حسب العضوية، ومنع القراءة العامة المباشرة لكل كيانات العيادات التجريبية عبر RLS. |
| التقارير | تطبيع بيانات كشف النشاط، التقييد حسب النطاق، طباعة البطاقة، وحماية تصدير CSV للإدارة. |
| الكتابة العامة والجلسة | حارس الأصل نفسه وحد الحجم، ورفض الكتابة غير المسموح بها في المسارات العامة، ورفض تسجيل الخروج من أصل خارجي قبل لمس الجلسة، ورفض وجهة دخول خارجية أو شبيهة بها قبل إعادة التوجيه. |
| أسرار النشر | بوابة النشر تمسح مفاتيح Supabase وTwilio وOpenAI ذات البنية الحساسة ومفاتيح `sk-` والرموز وملفات المفاتيح الخاصة؛ تُستبعد فقط قيم المثال الموسومة `REPLACE_ME`، ونجح اختبار سلبي مضبوط لقيمة وهمية طويلة في إثبات الرفض قبل النشر. |
| الواجهة والتحديث اللحظي | العربية والإنجليزية، سياسة CSP، التسجيل في PWA، والتعامل الآمن مع عدم الاتصال، وتجاهل إشعارات العيادة غير المرتبطة بطلبات الحجز قبل إعادة تحميل اللوحة. |
| تكاملات المزود الخارجي | مهلة صريحة واتصال مضبوط لكل من Twilio Verify ومحول دعم المنصة، مع تحويل فشل النقل واستجابة النموذج غير السليمة إلى حالة خدمة غير متاحة بدلاً من استثناء غير معالج. |
| استمرارية عمليات الخادم | عمليات RPC الخادمية مقيدة بمهلة 15 ثانية، ومنها تحليلات الإدارة وتفاصيل حجوزات العيادة وحسابات المشغلين وبحث العروض؛ ويحّول مسار الحجز انقطاع الاتصال أو انتهاء المهلة إلى استجابة `503` مضبوطة بدلاً من خطأ داخلي. ويغلف الحارس العام للمهلة تخزين الدعم والتحليلات وتحديثات ملف المريض وتحديات OTP وعمليات الحساب والإدارة والعيادة الحساسة؛ انتهاء المهلة يعيد فشلاً مضبوطاً بدلاً من انتظار غير محدود. يفصل مسارا بدء وتأكيد OTP بين تعطل خدمة تقييد المحاولات (`503`) وتجاوز الحد الفعلي (`429` مع `Retry-After`) بدلاً من خلط الحالتين. |
| أداء التقارير المالية | فترة التقرير المالي محكومة بخمس سنوات كحد أقصى وتواريخ تقويمية فعلية، ودوال التقرير تستخدم نطاقات `timestamptz` بتوقيت `Asia/Qatar` قابلة للاستفادة من فهرس `(clinic_id, start_at)`. |

## حدود الاختبار المعلنة

لا يثبت نجاح هذه المجموعة أن التطبيق خالٍ من كل خطأ نظرياً، ولا يمثل اختبار ضغط لحجوم آلاف أو ملايين الجلسات. فحص PWA المقيد يرفض مسارات API ويحد التزامن عند 50 طلباً لحماية الإنتاج؛ راجع [تقرير الأداء المقيد](CONTROLLED_READ_ONLY_PERFORMANCE_CHECK_2026-08-20.md) للأرقام وحدود القياس. محاولة OTP حية مقصودة في 20 أغسطس أعادت `503` بأمان قبل إنشاء تحدٍ أو تأكيد إرسال رسالة، لأن أسرار Twilio الثلاثة غير مضبوطة في بيئة الإنتاج؛ يوثق [دليل تهيئة OTP الحي](LIVE_OTP_CONFIGURATION_EVIDENCE_2026-08-20.md) الدليل والتنظيف. لم يُنشأ حجز حقيقي. يلزم إعداد مزود SMS ثم إعادة اختبار مقصود قبل ادعاء التسليم الخارجي، كما يلزم اختبار أداء معزول ومراقب قبل ادعاء مستوى حمل أعلى.

راجع [الحالة الإنتاجية الحالية](CURRENT_PRODUCTION_STATUS.md) لآخر موجز نشر وقيود تشغيلية، و[README الجذري](../README.md) للمسارات والعقود الكاملة.
