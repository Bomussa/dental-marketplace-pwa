# Change Gate — أسناني قطر

## الهدف

هذه البوابة تمنع إضافة تنفيذات مكررة أو تغييرات غير منضبطة قبل أن تصل إلى `main`. وهي طبقة آلية مساعدة وليست بديلًا عن مراجعة الكود أو اختبار الأمن أو التحقق من Supabase/Vercel.

المبدأ:

> **DISCOVER → VERIFY → MINIMAL CHANGE → TEST → RE-TEST → CLEAN → RELEASE CHECK**

## ما الذي يمنعه الـ Gate؟

1. أخطاء `git diff --check`.
2. ملفات مصدر متطابقة حرفيًا داخل المستودع.
3. ملف مصدر جديد يكون نسخة مطابقة فعليًا لملف مصدر موجود.
4. تكرار نفس تعريف التصدير بنفس التوقيع في أكثر من ملف، مع استثناء أسماء HTTP handlers الشائعة داخل Next.js routes.

كما يرفع تحذيرًا عند لمس حدود حساسة مثل:

- Supabase migrations.
- API routes.
- Supabase client/security code.
- RLS/policies/grants/revokes.
- booking/idempotency/service-role/secret boundaries.

التحذير لا يتجاوز الاختبارات ولا يثبت أن التغيير آمن؛ بل يعني أن المراجعة الأمنية/الهندسية إلزامية.

## ما الذي لا يدعيه الـ Gate؟

لا يمكن لفحص نصي أن يثبت وحده أن ميزتين متشابهتين business-wise هما duplicate حقيقي. لذلك لا يقوم الـ Gate بحذف ملفات أو دمج وظائف تلقائيًا، ولا يعتبر تشابه الأسماء أو التشابه الجزئي دليلًا كافيًا.

كما أنه لا يثبت:

- صحة RLS على قاعدة البيانات الحية.
- صحة الحجز المتزامن في Production.
- صحة تجربة iPhone Safari الحقيقي.
- صحة متطلبات العمل التي لا يمكن استنتاجها من الكود.

هذه البنود تبقى ضمن الاختبارات والمراجعة المناسبة.

## قاعدة التطوير

قبل إنشاء أي ملف أو API أو SQL object جديد يجب التأكد من أن المسؤولية غير موجودة أصلًا. تقليل عدد الملفات ليس هدفًا بحد ذاته؛ الهدف هو **Single Source of Truth + Single Responsibility + Zero Unnecessary Duplication**.

## التشغيل

محليًا:

```bash
npm run change:gate
```

وللتحقق الكامل:

```bash
npm run verify
```

في Pull Request إلى `main`، يعمل الـ Gate تلقائيًا باستخدام SHA الفرع الأساسي، ثم تعمل بقية اختبارات CI.

## سياسة الدمج

لا يكفي أن ينجح الـ Gate وحده. يجب أن تمر جميع الفحوص المطلوبة في CI وأن تتم مراجعة أي تغيير حساس. يوصى بحماية `main` بــ Pull Request + required status checks + منع force-push والحذف، وفق إعدادات GitHub للمستودع.
