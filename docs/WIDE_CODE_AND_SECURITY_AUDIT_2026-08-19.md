## ضوابط الأمان المثبتة

| الاختبار | النتيجة |
|---|---|
| حجز بلا جلسة | `401` قبل الكتابة. |
| دعم بلا جلسة | `401` قبل الكتابة. |
| تسجيل مريض بمدخل فارغ من الأصل نفسه | `400` قبل إنشاء حساب أو ملف مريض. |
| بدء أو تأكيد هاتف بلا جلسة | `401` قبل تشغيل التحقق. |
| تثبيت جهاز أو تحليلات اختيار من أصل خارجي | `403 forbidden_origin`. |
| جداول العميل الحساسة | سياسات صريحة تمنع العميل من الوصول إلى أسماء الحسابات وحسابات مشغلي العيادات، ولا توجد سياسة كتابة عامة لرسائل الدعم في نتيجة الفحص. |
| RPC ذات الامتياز | دوال الحجز وتغيير الحالة والتقارير وتسجيل الجهاز لا تمنح `EXECUTE` إلى `anon` أو `authenticated` في نتيجة الفحص. |

## ملاحظات Supabase التي لا تُعالج بتغيير شفرة تلقائي

أظهر مستشار Supabase الأمني تحذيراً واحداً: **حماية كلمات المرور المسرّبة معطلة**. هذا إعداد Auth لدى المزود، وليس عيباً يمكن إصلاحه بأمان عبر تغيير في المستودع، وقد يرتبط بخطة الخدمة. لم أفعّله ولم أغير خطة أو تكلفة أو إعداداً خارجياً تلقائياً. يظل الإجراء الاختياري للمالك هو تفعيل الميزة من إعدادات Supabase عند توافرها، وفق وثائق الحماية الرسمية.[1]

أظهر مستشار الأداء نتائج `INFO` عن فهارس لم تسجل استخداماً بعد، ومن بينها فهارس للحجز والبحث والتشغيل. لا يمثل ذلك دليلاً كافياً على أن الفهرس زائد؛ قد تكون هذه فهارس سلامة أو تخدم أحمالاً لم تقع بعد. لذلك لم تحذف أي فهارس أو قيود أثناء التدقيق.

## نتائج التحقق

| البوابة | النتيجة |
|---|---|
| `npm run verify` | ناجح: الفحص المسبق وTypeScript وESLint و**64** اختبار وحدة وبناء إنتاجي. |
| `npm run test:e2e` | ناجح: **48** اختبار متصفح في المسارات العامة والأمان واللغة وPWA. |
| `npm audit --omit=dev` | 0 ثغرات معروفة في تبعيات الإنتاج. |
| حمل محلي آمن — ملف manifest ثابت | 50/50 ناجح (`p95=208.52ms`) و100/100 ناجح (`p95=164.47ms`) بلا أخطاء. |

> قياس الحمل محلي وقراءة فقط لملف PWA ثابت؛ لا يثبت أداء قاعدة البيانات أو مقياس آلاف/ملايين المستخدمين، ولا يبرر إرسال حمل مرتفع إلى الإنتاج.

## حدود التدقيق

لم ينشئ التدقيق حجزاً أو ملف مريض أو رسالة SMS أو تعديل بيانات تشغيلية. لا يثبت التقرير تسليم SMS أو تصرف مسارات تتطلب حسابات أدوار تشغيلية حية في هذه الجولة. لا يقدم ادعاءً مطلقاً بخلو النظام من كل خطأ مستقبلي؛ يقدم الأدلة القابلة لإعادة الإنتاج ضمن النطاق أعلاه.
