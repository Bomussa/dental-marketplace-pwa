# تدقيق الاعتمادية الشامل — 20 أغسطس 2026

> هذا تقرير تدقيق **قراءة فقط** ما عدا تصحيح توثيق سجل الترحيلات. لم يُنشأ حجز أو حساب أو ملف مريض، ولم تُرسل رسالة SMS أو إشعار خارجي، ولم يُعدّل مخطط قاعدة البيانات أو سياسات RLS في هذه الجولة.

## الهدف والنطاق

راجعت هذه الجولة مسارات الكتابة الحساسة، عمليات الحجز والتحقق من الهاتف، طبقات الصلاحيات، قيود منع التكرار، اتصالات المزود الخارجي، حالة النشر، وسجلات التشغيل. يثبت التقرير الحالات الملاحظة وقت التدقيق فقط، ولا يدّعي استحالة ظهور أخطاء مستقبلية أو سعة تجارية عند أحجام غير مقاسة.

| مجال التدقيق | الدليل أو النتيجة المثبتة |
|---|---|
| خط الأساس الساكن | نجحت `predeploy:check` وTypeScript وESLint من شجرة عمل نظيفة ومتطابقة مع `origin/main` وقت بدء التدقيق. |
| مسارات الكتابة | حُصرت مسارات API وعمليات الكتابة؛ مسارات الحجز وOTP والدعم والتسجيل والتثبيت والأحداث تستخدم حواجز أصل أو حجم أو معدل بحسب عقدها، وتتحقق المسارات المقيّدة من الجلسة قبل التعديل. |
| الحجز والتكرار | دالة الحجز الذرية تقفل الموعد، وتستخدم مفتاح idempotency فريداً لكل حساب، وتتعامل مع تعارضات المورد أو الممارس قبل تثبيت الحجز. |
| OTP | مسار البدء والتحقق خادميان؛ اتصال Twilio محكوم بمهلة، وإنهاء التحقق يتم عبر RPC ذري يعيد نتيجة التحقق الملتزم بها بأمان عند إعادة المحاولة. |
| الدعم الخارجي | محول نموذج الدعم مقيد بمهلة 15 ثانية ويحوّل فشل النقل أو الرد غير السليم إلى `SUPPORT_UNAVAILABLE` بدلاً من كشف استثناء داخلي. |
| بيانات الإنتاج | فحص مكرر قراءة فقط وجد صفر مجموعات تكرار في: رمز العلاج، متغير العلاج ضمن العلاج، مفتاح idempotency للحجز ضمن الحساب، والرقم الشخصي لملف مريض نشط. |
| سجلات Supabase | لم يظهر ملخص أخطاء HTTP لواجهة قاعدة البيانات خلال نافذة 24 ساعة. أخطاء PostgreSQL المحدودة المسجلة جاءت تحت دور `postgres` وارتبطت باستعلامات إدارية غير متوافقة سابقة، لا بطلبات التطبيق الموثقة. |
| سجلات Vercel | لم يظهر مستكشف أخطاء التشغيل أي عنقود أخطاء وقت الفحص خلال آخر 24 ساعة. |
| الترحيلات | سجل الإنتاج يثبت 78 ترحيلاً. تطابقت أسماء الترحيلات المحلية من 16 إلى 78 مع الأسماء البعيدة؛ غياب ملفات 1 إلى 15 المحلية موثق تاريخياً في سجل الترحيلات ولا يثبت انجرافاً جديداً. |

## نتيجة مستشاري قاعدة البيانات

أظهر مستشار الأمان ملاحظة واحدة فقط: **حماية كلمات المرور المسرّبة معطلة** على مستوى Supabase Auth. التطبيق يفرض حالياً كلمة مرور من 12 إلى 128 حرفاً تتضمن حرفاً صغيراً وكبيراً ورقماً، لكن فحص قاعدة كلمات المرور المسرّبة ميزة إعداد خدمة خارجية ولا يُفعل تلقائياً هنا. يلزم قرار واعٍ في إعدادات Supabase وخطة الخدمة المناسبة قبل تغيير هذه الحالة.

أما مستشار الأداء فأظهر فهارس غير مستخدمة وتحذيرات تداخل سياسات RLS المسموح بها لجداول تشغيلية. لم تُحذف الفهارس ولم تُدمج السياسات في هذه الجولة: هذه التحذيرات لا تثبت خللاً وظيفياً، وإزالة فهرس أو دمج سياسة وصول من دون اختبار مصفوفة الأدوار والبيانات الواقعية قد يضر بالأداء أو بالنطاق المطبق للصلاحيات.

## التصحيح المنجز

كان التعارض المثبت الوحيد في التوثيق: سجل `REMOTE_APPLIED_MIGRATIONS.md` كان ينتهي عند الترحيل 74 رغم أن الإنتاج يحتوي كذلك على الترحيلات 75 إلى 78. جرى تحديث السجل بأسماء وإصدارات الترحيلات الأربعة، وبتوضيح طريقة المطابقة الصحيحة بالاسم بدلاً من افتراض تطابق بادئة اسم الملف مع رقم الإصدار البعيد.

## بوابات التحقق المطلوبة قبل أي تغيير لاحق

| التغيير المقترح | شرط القرار قبل التنفيذ |
|---|---|
| تفعيل حماية كلمات المرور المسرّبة | التحقق من توفر الميزة في خطة Supabase واعتماد تغيير الإعداد التشغيلي. |
| دمج سياسات RLS | اختبار مستقل لكل دور: مريض، موظف استقبال، مدير عيادة، مالك عيادة، وإدارة منصة؛ ثم قياس قبل وبعد. |
| حذف فهرس غير مستخدم | بيانات إنتاج ممثلة، وخطة استعلام لمساراته، ومراقبة أثر بعد الإزالة في بيئة معزولة. |
| تحميل بالحجم الكبير | بيئة غير إنتاجية، بيانات مصطنعة مصرح بها، SLOs وحدود تكلفة ومراقبة متفق عليها. |
